# Maintainer Guide — triaging & re-reviewing gsd-core with the toolkit

*How a maintainer (or CODEOWNER) uses the toolkit to sweep the repo, triage an incoming issue,
re-review a stalled PR, and run the release/ruleset assists. For the big picture see the
[Overview](overview.md); for the contributor side see the [Contributor Guide](contributor-guide.md).*

---

## The maintainer posture

Every maintainer path here is **advisory and read-only by default** — an assist surfaces evidence and
**stops for your call**. Nothing mutates GitHub or the tree without an explicit `--apply` flag or a merge
token. Three rules run through all of them:

- **Evidence is exogenous.** Every verdict and every number (CI conclusion, test count, `lint:ci`,
  `git diff`) must come from a command **you actually ran and captured** — never synthesized. If you
  couldn't run it, write "not run." Fabricated verification is the exact dishonesty the pipeline exists
  to prevent.
- **Respect the intake perimeter.** The repo's LIVE GitHub Actions (auto-close-unsolicited-prs,
  require-issue-link, pr-title-validator, dedupe, version-gate, close-draft-prs,
  dismiss-unauthorized-approvals) are real — never work around them.
- **Disclaimer on every tracker write:** `> *Generated by AI during triage; reviewed and posted by a
  human maintainer (@you).*`

## 0. Install

Same driver as the contributor side:

```bash
node bin/contrib-capability.cjs install
node bin/contrib-capability.cjs status
```

The maintainer assists are surfaced through `/gsd-*` commands and backed by the
[`maintainer-review-sweep`](../skills-reference.md#maintainer-review-sweep) skill.

## 1. The daily sweep — `/gsd-review-sweep`

Ranks open issues + PRs by **cost-to-advance**, presents the buckets, and **awaits your pick** before any
per-PR re-review.

```text
/gsd-review-sweep                       # sweep mode: rank + present, then stop for your pick
/gsd-review-sweep re-review #1532        # re-review one PR
/gsd-review-sweep clear #1532 merge=#1532 # re-review + merge, only if a plain CLEAR
```

The pipeline (an adversarial gate between every phase; re-fetch live state before any write):

1. **Scope** — repo, default branch (`next`), exclude-author (the lead maintainer — filter for *action*,
   never hide their high-severity/security items), merge token.
2. **Discover** — list open issues + PRs.
   - **2b. Prior-adjudication recall** *(advisory)* — before ranking, ask MemPalace what a past session
     already concluded about the surfaced `#numbers`: already adjudicated? a PR on this defect already
     cleared or blocked, and on what evidence? Search **un-scoped** — a wing-scoped miss is not evidence
     of absence. If a concurrent `mine` holds the palace, retry once then skip; it never stops the sweep.
3. **Cross-reference in-flight work** — duplicate/overlapping issues, issue↔PR links, PR↔PR file
   collisions; group related `#numbers` so nothing is handled in isolation.
4. **Prioritize** — quick-fix vs. highest user impact; surface data-loss/security/runtime-broken first.
5. **State & cost-to-advance** — rank by cheapness: *approved+rebase* < *brief-ready, no PR* <
   *re-review round* < *needs design*. A re-review beats a fresh design pass.
6. **Stranded-value sweep** — issues with a complete brief but a missing `ready-for-agent` label
   (the brief is the expensive part; the label is the only thing gating dispatch).
7. **Ball-in-court** — anchor to the latest **`CHANGES_REQUESTED`** review (not the latest review of any
   kind): author pushed after it → ball on reviewer; otherwise author still owes changes.
8. **Authority reality** — role, CODEOWNERS, and **rulesets** (note `enforcement: evaluate` = audit-only,
   so CI "green" from the ruleset is *not* a gate — read real check-runs yourself).
9. **Present & select** — show the ranked buckets and await your pick; then per-PR re-review.
10. **Capture the outcome** *(advisory)* — file the verdict, its evidence, and specifically the
    **exogenous-pass delta**: what the fresh reviewer caught that your own pass missed. That delta is the
    most reusable thing a sweep produces, and it otherwise evaporates with the session. A failed capture
    never blocks or changes a verdict.

> **The recall/capture pair is advisory and model-driven** — no hook, no gate, no receipt. Per
> [CTK-ADR-0001 §Decision.1](../adr/CTK-ADR-0001-harness-boundary-enforcement.md) hooks lock *outcomes*,
> not steps. Note also the **`--wing` asymmetry**: omit it when you *search* (hook-captured conversation
> lands in a separate `sessions` wing), but pass it when you *mine*, because it defaults to the staging
> directory's name and silently creates a junk wing.

## 2. Triaging an incoming issue — `/gsd-triage-assist`

Advisory first-triage of one new issue. **No GitHub mutation by default** — mutations (e.g. the
`needs-triage` strip) only behind `--apply` on explicit, per-issue authorization.

```text
/gsd-triage-assist #1601
/gsd-triage-assist apply the role and strip needs-triage on #1601   # explicit apply
```

It runs in two parts, **in order** (see `skills/maintainer-review-sweep/triage-assist.md`):

### Part A — the advisory surface pass (the doer)
`node bin/triage-assist.cjs` invokes LIVE `issue-dedupe` (duplicate signal), LIVE `issue-version-gate`
(bug-report version finding), and reads the canonical role **only** from LIVE
`docs/agents/triage-labels.md`. A LIVE script that can't load fails **LOUD** — never a false "clean".

### Part B — the advancement artifacts (mirror the maintainer's live practice)
1. **Settle bug-vs-by-design against the design record — BEFORE you confirm.** Grep `docs/prd/`,
   `docs/adr/`, `docs/explanation/`; open and **quote** the governing clause. *Intended AND implemented* →
   by-design (`wontfix`/docs). *Intended but NOT fully implemented* → still a **`confirmed-bug`** (an impl
   gap — the common trap). *No design record* → route to `/grilling` + `/domain-modeling`, don't guess.
2. **Confirmed bug → post the Agent Brief.** *Reproduction (empirical) → Root cause (`file:line`) → Fix
   (reuse the source of truth; no Generative-Fix-Divergence) → Acceptance criteria → Verify →
   **Authorization + scope fence** ("go ahead; scoped to X only; do not alter Y").* The brief IS the
   expensive artifact `ready-for-agent` gates dispatch on; a bare label strands the issue.
3. **Enhancement/feature → post the approval-conditions checklist.** A **hard caveat** (the one change
   that would over-reach — forbid it) + a **Conditions (all required before merge)** checkbox list. No
   contributor code before `approved-enhancement`/`approved-feature`.
4. **Route capability-shaped work → `capability-candidate`.** If it extends behavior at an ADR-857
   extension point (runtime/host, command family, hook, skill) rather than altering core dispatch, steer
   it to the **capability** route, not a core patch. (Not a substitute for the `approved-*` gate.)

Label mechanics live in [`labels.md`](../../skills/maintainer-review-sweep/labels.md): remove
`needs-triage` on any state transition; never hand-edit bot-managed labels (`possible-duplicate`,
`needs-version`); `version-exempt` is referenced by the gate but **not a live label** — don't try to
apply it.

## 3. Re-reviewing a PR — the heavy procedure

For each selected change-requested PR, the skill's `re-review.md` runs a rigorous procedure. The
load-bearing moves:

- **Re-fetch live state + treadmill guard.** PR HEAD OID, reviews, labels, real CI conclusions. Stop
  after ≥2 AI rounds with no new substantive change (dismiss-stale-on-push loop).
- **Recall prior rounds** *(advisory, step 2)*. What did a *previous session* conclude about this PR,
  and why? This is distinct from the treadmill guard above, which counts rounds **posted on GitHub** —
  the timeline does not carry the reasoning, only the artifacts.
- **Merge-no-op / revert detection.** Confirm the PR still changes what it claims (a conflict resolved to
  the base side can silently revert it).
- **Generated-vs-source (ADR-457).** `bin/lib/*.cjs` is generated from `src/*.ts` — a direct edit is a
  Blocker; verify the source changed and `build:lib` is clean.
- **Local verification — actually run it.** `npm ci`, `build:lib`, `lint:ci`, the named tests; capture
  real counts. Fork PR you can't fetch → mark local "not run (fork PR — CI matrix held)" and treat **CI
  conclusions as the evidence**; state the read-only posture in the review body.
- **CI attribution.** Grep the failed step for the **literal** failing assertion first; don't infer the
  cause from nearby output.
- **Fail-first + no vacuous tests + Generative-Fix-Divergence** (steps 4b/4c) — the fix must add a
  proven-fail-first regression test, no zero-iteration pass-always test, and must not recreate its root
  cause by hardcoding a literal instead of importing the source of truth.
- **ADR & source-of-truth pass** + **capability-vs-core boundary** (ADR-857/1244) + **changeset/docs
  policy**.
- **Two orthogonal isolated passes (`CI.GATE.orthogonal-review-required`)** — `/code-review`
  (correctness+standards) **and** `/security-review`, always, with an explicit `### Security` verdict line.
- **Exogenous self-check** — before any CLEAR, dispatch a *fresh* reviewer given only the diff + blocking
  findings + governing ADRs (never your verdict), then `trust-but-verify` its report against the primary
  source.
- **Verdict + delivery.** Grade findings on the multi-tier scale — **Blocker / Major / Minor / Nit** (or
  High/Med/Low); a Blocker *or* a top-tier Major/High drives Request-changes. Deliver as a **single
  human-submitted formal review** with the size-bounded template and the AI disclaimer. Merge **only**
  with the token AND a plain evidence-backed CLEAR AND no other maintainer's unresolved change-request.

## 4. Release pre-flight — `/gsd-release-preflight`

Advisory, **read-only**. Runs the four LIVE gsd-core release scripts non-mutatingly, aggregates **every**
failure (no fail-fast), exits nonzero on any blocker.

```bash
cd ~/repos/gsd-core && node ~/repos/gsd-contrib-toolkit/bin/release-preflight.cjs
```

Any `[FAIL]` (integrity/manifest/version drift, a smoke failure, or a LOUD missing-LIVE-script error)
blocks the release. Never mutates the tree or GitHub.

## 5. Ruleset governance drift — `/gsd-ruleset-drift`

Compares **declared** `.github/rulesets/*.json` against the **live** `gh api …/rulesets` state and
surfaces drift in `enforcement`, presence, or the `rules` set.

```bash
cd ~/repos/gsd-core && node ~/repos/gsd-contrib-toolkit/bin/ruleset-drift.cjs           # read-only report
cd ~/repos/gsd-core && node ~/repos/gsd-contrib-toolkit/bin/ruleset-drift.cjs --apply   # remediate (explicit)
```

Read-only by default; the LIVE remediation runs **only** behind `--apply`. A failed declared/live read is
a LOUD error, never a false "no drift."

## 6. Merge discipline (the guardrails)

- **Ball-in-court** anchors to the latest `CHANGES_REQUESTED`, not the latest review of any kind — a
  non-owner's approval does not clear an owner's change-request.
- **Read real check-runs on the head SHA** — branch protection is evaluate-mode; a changeset-only commit
  can hide a stale failed Tests run.
- **Don't merge over another maintainer's *unresolved* change-request.** If your re-review *verifiably*
  confirms they were addressed, **dismiss** the stale CR with an evidence-cited message — but *only* on
  explicit human authorization (dismissal is consequential and hard to reverse).
- **Stop at merge-readiness** unless the invocation carries an explicit `merge=#N` token.
